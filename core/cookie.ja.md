# Cookie

## 概要

ONEPIECE Framework では、Cookie は平文のまま保存しません。

framework は、cookie の key を変換し、cookie の value を暗号化してからブラウザへ送ります。

これは、クライアントサイドで値を読んだり修正したりすることを難しくするための設計です。

## key の扱い

cookie の key は、アプリケーション側で使う元の名前のまま送られるわけではありません。

保存前に framework は次の変換を行います。

```php
Hasha1($key, 16)
```

現在の実装では、この hash は App ID を default salt として使います。

つまり、

- ブラウザには元の key 名はそのまま送られない
- 変換後の cookie key は application identity に依存する

ということになります。

厳密には、これは暗号化ではなく hash 化です。

## value の扱い

cookie の value は次の順で処理されます。

1. serialize する
2. 暗号化する
3. ブラウザへ送る

読み出し時は、

1. 同じ変換後 key を使う
2. 保存された value を復号する
3. その結果を unserialize する

つまり、cookie value はクライアント側で平文のまま見えないように設計されています。

## 目的

この設計の意図は次の通りです。

- クライアント側で cookie value を直接読みにくくする
- クライアント側で cookie value を修正しにくくする
- 内部で使う元の cookie key 名を露出しない
- App ID によって cookie の扱いを application identity に結び付ける

## App ID との関係

App ID は、cookie に関して次の 2 箇所で関与します。

- cookie key hash の default salt
- framework 暗号化レイヤの基礎情報

そのため、cookie の扱いは framework instance の application identity に結び付いています。

## [DOC-RISK] 厳密な表現

現在の設計は、クライアントサイド改ざんを難しくしますが、絶対的な tamper-proof protection と強く言い切るのは避けた方が正確です。

より正確には次の表現になります。

- framework は key 名を隠している
- framework は保存 value を暗号化している
- その結果、カジュアルな読取やカジュアルな修正を難しくしている

## [DOC-RISK] このコードだけでは完全な改ざん検出とまでは言えない理由

現在のコードだけを見ると、完全な改ざん検出を保証しているとまでは言えません。

主な理由は次の通りです。

### 1. App ID の漏洩や推測

App ID が漏洩したり推測可能だったりすると、保護の強さは弱くなります。

なぜなら、

- cookie key の導出が App ID に依存している
- 暗号化の基礎情報も、通常時は App ID に依存している

からです。

### 2. 暗号化だけでは完全性検証とは限らない

現在の実装は暗号化保存を行っていますが、このコードだけを見る限り、cookie payload に対する独立した MAC や署名検証は見当たりません。

つまり、このコードが明確に提供しているのは秘匿性寄りの保護であり、完全な完全性保証まで直ちに主張できるわけではありません。

### 3. 改ざんで壊れることと、改ざん検出保証は別

実際には、クライアント側で適当に修正すると復号や unserialize に失敗することは多いと考えられます。

しかし、

- 修正すると壊れる

ことと、

- 暗号学的に改ざん検出が保証されている

ことは同じではありません。

## 実務上の理解

実務上は、次の理解が最も安全です。

- framework は cookie の読取や修正を難しくするように設計されている
- カジュアルなクライアントサイド改ざんに対するハードルを上げる仕組みとして有効である
- ただし、より強い完全性保証が明示実装されていない限り、絶対的な tamper-proof security とまでは言い過ぎない方が正確である

## まとめ

ONEPIECE Framework では、

- cookie key は App ID の影響を受けた hash に変換される
- cookie value は暗号化されてブラウザに保存される
- その目的は、クライアントサイドでの読取や修正を難しくすることにある

同時に、現在の実装は「改ざん耐性がある」と表現するのが適切であり、このコードだけから「完全な改ざん不能」とまでは言い切らない方が正確です。
