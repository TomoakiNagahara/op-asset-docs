# 2026-05-14 Agent Review 2

## 対象

この記録は、同じ作業中に agent が行った 2 つ目の documentation mistake を残すものです。

誤りは、公開され得るドキュメントに、秘匿性の高い deployment 固有の verification header details を書いたことでした。

## ユーザーから指摘された内容

ユーザーは、secret または deployment 固有の verification key name や value を、公開される可能性のある documentation に含めてはいけないと指摘しました。

secret value そのものを password として説明していなくても、正確な header name、token name、verification key name は、deployment の保護機構の一部を明かすため sensitive です。

## Agent の不適切な挙動

agent は、review document に具体的な verification header name を書きました。

これは次の理由で誤りでした。

- Public documentation は private deployment mechanism を公開してはいけない。
- 具体的な secret header name や token name は、verification layer の security value を下げる。
- Review document は lesson を残すべきであり、implementation-specific secrets を公開すべきではない。

## 正しい方向

具体的な secret name ではなく、一般化した表現を使います。

- origin verification mechanism
- trusted proxy verification
- deployment-owned secret header
- private verification token

ユーザーが公開目的だと明示しない限り、実際の key name、header name、token name、value は書きません。

## 教訓

[DOC-RISK] 公開される可能性のある repository documents に、sensitive な key name、header name、token name、value を含めない。

[DOC-RISK] private verification mechanism の正確な名前も、その値だけでなく sensitive として扱う。

[DOC-GAP] incident や review documentation を書く前に、それぞれの concrete identifier が public architecture、internal implementation detail、secret deployment detail のどれかを分類する。

[DOC-FUTURE] Agent review documents は security lesson を適切な抽象度で説明し、deployment の trust boundary を回避する助けになる details を公開しない。
