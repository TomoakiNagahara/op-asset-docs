# 2026-05-16 Agent Review

## 対象

この記録は、`OP()->Template()` に関する作業中に行った documentation placement の修正を残すためのものです。

直接の問題は、`OP()->Template()` の current As-Is behavior をどこに document 化するべきか、という点でした。

## ユーザーから指摘された内容

ユーザーは、`OP()->Template()` の As-Is behavior が `OP_TEMPLATE` trait に依存していることを明確にしました。

そのため、current behavior は関係の薄い skeleton document や gap document に重複して書くのではなく、trait documentation に集約するべきです。

重要な点は次です。

- 同じ内容を異なる file に散らばらせない。
- behavior owner から直感的にわかる file path を選ぶ。
- documentation を保存する file は、その内容の責務に相応しい場所を選ぶ。
- 他の document は implementation detail を繰り返さず、owner document へ link または参照する。

## Agent の不適切な方向

agent は当初、`OP()->Template()` の current behavior を複数箇所に重複して書きました。

- `asset/core/trait/docs/op-template.md`
- `asset/core/trait/docs/op-template.ja.md`
- `asset/docs/skeleton/template-directory.md`
- `asset/docs/skeleton/template-directory.ja.md`
- `asset/docs/important-gaps.md`
- `asset/docs/important-gaps.ja.md`

これにより、同じ As-Is implementation detail が、責務の異なる複数 document に現れました。

これは、将来 `OP_TEMPLATE` が変わった場合に複数 document の更新が必要になり、reader にとっても source of truth がわかりにくくなるため誤りでした。

## 正しい方向

修正後の構造は次です。

- `OP()->Template()` の current As-Is behavior は `asset/core/trait/docs/op-template.md` に置く。
- Japanese mirror は `asset/core/trait/docs/op-template.ja.md` に置く。
- `asset/docs/skeleton/template-directory.md` は、intended template-directory specification と operational guidance に集中させる。
- `asset/docs/important-gaps.md` は mismatch の index として扱い、詳細な As-Is owner にはしない。
- skeleton document と gap document は、current `OP()->Template()` As-Is behavior について trait docs を参照する。

これにより、implementation-dependent behavior は、その behavior を所有する file である `asset/core/trait/OP_TEMPLATE.php` の近くに置かれます。

## 教訓

[DOC-RISK] 1つの behavior の As-Is detail を、責務の異なる複数 document に重複して書かない。

[DOC-RISK] current behavior が特定の class、trait、function、unit、module file に依存する場合、可能な限り、その owner の近くに As-Is documentation を置く。

[DOC-GAP] owner 以外の document が同じ current behavior を必要とする場合、詳細をコピーせず、owner document への参照を追加する。

[DOC-GAP] documentation path は、最初にその話題が見つかった page ではなく、code owner と responsibility boundary から直感的にわかる場所を選ぶ。

[DOC-FUTURE] documentation を整理するときは、intended specification、current As-Is behavior、curated gap index の区別を保つ。
