# 2026-05-14 Agent Review

## 対象

この記録は、`asset/config/_admin.php` と `asset/core/include/isAdmin.php` に関する作業中に、agent が行った不適切な判断を残すためのものです。

元の目的は、Cloudflare 配下の公開環境で admin 判定を正しく動かすことでした。

## ユーザーから指摘された内容

ユーザーは次の重要な設計制約を明確にしました。

- `asset/core/include/isAdmin.php` は現行で正しく動いている core 機能である。
- core の admin 判定はシンプルに保つべきである。
- core は、config に設定された許可 IP アドレス 1 つと `REMOTE_ADDR` を比較するだけでよい。
- Cloudflare 固有の処理は core ではなく、local application または deployment 側の config に置くべきである。
- 今回修正すべき場所は `asset/config/_admin.php` だけだった。
- `HTTP_CF_CONNECTING_IP` は偽装できるため、origin verification なしに信用してはいけない。
- Cloudflare IP ranges は追加・削除されるため、source code に hardcode する前提は不適切である。
- この deployment では、正しい origin verification mechanism があるなら trusted proxy 経由であり、その内側では trusted proxy の client IP header は存在する前提でよい。

## Agent が行った不適切な修正

方向修正前に、agent は次の悪い修正を行いました。

- `asset/config/_admin.php` だけで解決すべき問題なのに、`asset/core/include/isAdmin.php` を変更した。
- proxy や Cloudflare 固有の logic を core に追加し、単純であるべき core function を不必要に複雑にした。
- spoofing risk を十分に尊重する前に、`HTTP_CF_CONNECTING_IP` を直接比較に使った。
- Cloudflare IP ranges を source code に hardcode した。
- 既存の core boundary を尊重する前に、local Cloudflare range file を追加した。
- 不適切な core behavior に合わせて core documentation まで変更した。

これらの修正は、deployment 固有の処理を core に持ち込み、`isAdmin()` の責務を広げた点で誤りでした。

## 正しい方向

修正後に確認された正しい設計は次です。

- `asset/core/include/isAdmin.php` はシンプルなまま保つ。
- core documentation も単純な core rule と一致させる。
- Cloudflare 固有の処理は `asset/config/_admin.php` の中で完結させる。
- Cloudflare request header を信用する前に、deployment 側の origin verification を使う。
- 検証済み trusted-proxy request が許可された client IP を持つ場合だけ、`OP::_ADMIN_IP_` に現在の `REMOTE_ADDR` を設定する。

これにより、core は `REMOTE_ADDR` と config の admin IP を比較するだけ、という contract を保てます。

## 教訓

[DOC-RISK] deployment 固有の config file で解決できる問題では、core code を変更しない。

[DOC-RISK] 1つの deployment environment に対応するために、安定している core function を複雑にしない。

[DOC-RISK] trusted path から来た request だと検証する前に、client が送れる request header を信用しない。

[DOC-GAP] `asset/config/_admin.php` のような local override file の確認を依頼された場合、core 変更を提案する前に override boundary を確認する。

[DOC-FUTURE] trusted proxy handling を framework feature にする場合は、`isAdmin()` に ad hoc に追加するのではなく、明示的な configuration contract として設計する。
