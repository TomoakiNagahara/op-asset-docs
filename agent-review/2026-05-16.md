# 2026-05-16 Agent Review

## Scope

This note records a documentation placement correction made during work on `OP()->Template()`.

The immediate issue was where to document the current As-Is behavior of `OP()->Template()`.

## What The User Pointed Out

The user clarified that the As-Is behavior of `OP()->Template()` depends on the `OP_TEMPLATE` trait.

Therefore, the current behavior should be documented in the trait documentation, not duplicated across unrelated skeleton or gap documents.

The key points were:

- Do not scatter the same content across different files.
- Choose a file path that is intuitive from the behavior owner.
- Store documentation in the location that best matches the responsibility of the content.
- Other documents should link or refer to the owning document instead of repeating implementation details.

## Incorrect Agent Direction

The agent initially duplicated `OP()->Template()` current behavior in multiple places:

- `asset/core/trait/docs/op-template.md`
- `asset/core/trait/docs/op-template.ja.md`
- `asset/docs/skeleton/template-directory.md`
- `asset/docs/skeleton/template-directory.ja.md`
- `asset/docs/important-gaps.md`
- `asset/docs/important-gaps.ja.md`

This made the same As-Is implementation detail appear in several documents with different ownership scopes.

That was wrong because future changes to `OP_TEMPLATE` would require updating multiple documents, and readers would not have one obvious source of truth.

## Correct Direction

The corrected structure is:

- Put the current As-Is behavior of `OP()->Template()` in `asset/core/trait/docs/op-template.md`.
- Put the Japanese mirror in `asset/core/trait/docs/op-template.ja.md`.
- Keep `asset/docs/skeleton/template-directory.md` focused on intended template-directory specification and operational guidance.
- Keep `asset/docs/important-gaps.md` as an index of the mismatch, not as the detailed As-Is owner.
- Make skeleton and gap documents refer to the trait docs for current `OP()->Template()` As-Is behavior.

This keeps implementation-dependent behavior beside the file that owns it: `asset/core/trait/OP_TEMPLATE.php`.

## Lessons

[DOC-RISK] Do not duplicate one behavior's As-Is details across documents with different responsibility scopes.

[DOC-RISK] When current behavior depends on a specific class, trait, function, unit, or module file, place the As-Is documentation beside that owner whenever possible.

[DOC-GAP] If a document outside the owner needs the same current behavior, add a reference to the owner document instead of copying the details.

[DOC-GAP] Choose documentation paths that are intuitive from the code owner and responsibility boundary, not only from the page where the topic was first noticed.

[DOC-FUTURE] When reorganizing documentation, preserve the distinction between intended specification, current As-Is behavior, and curated gap indexes.
